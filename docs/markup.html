Markup contract

The classes you put on wrapper divs to lay out panels and charts

mathviz has almost no JavaScript API for layout. You put a handful of classes on wrapper <div>s – in Quarto, a fenced div ::: {.ojs-panel} – and the library lays the controls out and finds what to enhance. This page is every class and attribute you write yourself, with a live example of each. (The classes the library generates, which you never write, are listed under Internals.)

VM = window.VM
vmTheme = Generators.observe(notify => VM.plotting.onThemeChange(notify))
chartColors = VM.plotting.colors(vmTheme)

At a glance

Class / attribute Put it on Effect
ojs-panel a div around Inputs.* cells the control-panel chrome; restyles every input inside
ojs-row / ojs-grid the same div, or a nested one one wrapping flex row / an auto-fit grid
ojs-fill / ojs-auto / ojs-end an input’s wrapper (classList.add) fill the row / natural width / push to the right edge
ojs-chart-block a div around the chart cell(s) anchor for the legend; what fullscreen enlarges
ojs-chart-controls a div inside the block, holding sliders a bar directly above the chart that comes along into fullscreen
ojs-svg-block alongside ojs-chart-block, for SVG charts adds the fullscreen button Plotly charts get from the modebar
plotly-box-large the Plotly graph div the one shipped chart size
vm-swatch vm-swatch-alt (one modifier per palette color, plus -accent) a <span> in prose tints a color word with the matching palette color
vm-invalid an <input> red border and tint for a field that failed validation
data-vm-play="off" a slider or any ancestor opt that slider out of the play button
data-example-field="…" a viewof element a stable handle for applyExampleParams

Panels

ojs-panel

The look: padding, border, rounded corners, a surface background, and consistent styling of every input, select and button inside it, with labels stacked above controls so a row of them bottom-aligns.

It is look only. Pair it with ojs-row or ojs-grid for layout. Don’t nest one panel inside another (the border and background double up); nest a bare ojs-row or ojs-grid div instead.

ojs-row

One wrapping row, bottom-aligned. The first control stretches to fill; the last takes its natural width; anything between takes its natural width too. That is the shape of most panels: a wide expression field, then a couple of small controls, then a button.

viewof rowF = Inputs.text({label: "f(x)", value: "x^2 - 2"})
viewof rowX0 = Inputs.text({label: "x₀", value: "1"})
viewof rowGo = Inputs.button("Plot")

ojs-grid

An auto-fit grid of equal columns (about 250 px each; fewer on narrow screens), bottom-aligned. For a panel of several similar controls where none should dominate.

viewof gridA = Inputs.range([0, 1], {label: "alpha", step: 0.01, value: 0.5})
viewof gridB = Inputs.range([1, 50], {label: "n", step: 1, value: 10})
viewof gridC = Inputs.select(["Euler", "RK4"], {label: "method"})
viewof gridD = Inputs.checkbox(["show error", "show exact"], {label: "overlay", value: ["show exact"]})

ojs-fill, ojs-auto, ojs-end

Per-control overrides, added to the viewof element from the cell that creates it:

viewof expr = {
  const view = Inputs.text({label: "f(x)", value: "sin(x)"})
  view.classList.add("ojs-fill")
  return view
}
Class Effect
ojs-fill Full width; a text input inside becomes a wide box the reader can drag wider – for a long expression.
ojs-auto Natural width, in a row that would otherwise stretch it.
ojs-end Pushes the control to the right edge, in a row or a grid.

Charts

ojs-chart-block

The wrapper around a chart and its companions. A floating legendOverlay is positioned against it, and it is what the fullscreen button enlarges – so a controls bar and legend inside it come along, and the chart keeps its aspect ratio.

Every chart wants one, even a chart that has neither a legend nor controls today. It also lets a chart in a layout-ncol column shrink with the column instead of forcing it wide.

ojs-chart-controls

A direct child of the chart block, holding the sliders that drive the chart – an iteration count, a step size. It renders as a bar directly above the chart, stays with the chart in fullscreen, and lays its controls out for that width: fluid slider tracks, compact number fields, labels beside controls.

Sliders in it get the play button. Combine with ojs-grid (class="ojs-chart-controls ojs-grid") for several sliders side by side.

viewof ctrlN = Inputs.range([1, 12], {label: "iterations n", step: 1, value: 4})
{
  const g = x => Math.cos(x)
  let x = 1
  const xs = [x], ys = [0]
  for (let i = 0; i < ctrlN; i++) { const gx = g(x); xs.push(x, gx); ys.push(gx, gx); x = gx }
  const curveX = [], curveY = []
  for (let i = 0; i <= 100; i++) { const t = i / 100 * 1.6; curveX.push(t); curveY.push(g(t)) }
  const div = document.createElement("div")
  div.style.height = "300px"
  Plotly.newPlot(div, [
    {x: curveX, y: curveY, name: "cos x", line: {color: chartColors.fn}},
    {x: [0, 1.6], y: [0, 1.6], name: "y = x", line: {color: chartColors.muted, dash: "dot"}},
    {x: xs, y: ys, name: "cobweb", line: {color: chartColors.alt, width: 1.5}, mode: "lines+markers", marker: {size: 5}}
  ], {showlegend: false, xaxis: {range: [0, 1.6]}, yaxis: {range: [0, 1.1]}, margin: {t: 8}})
  VM.plotting.autoResize(div)
  return div
}

ojs-svg-block

For a chart drawn as inline SVG – Observable Plot, or a hand-built <svg> – which has no Plotly modebar. Put it on the same element as ojs-chart-block and nothing else: the library adds a fullscreen button pinned to the top-right corner of the figure, centers the figure in the block, and keeps its aspect ratio in fullscreen. The button survives re-runs of the cell.

The VM.discreteMath page and the starter’s observable-plot.qmd use it. Hover the chart there to see the button.

plotly-box-large

Full width, about three-quarters of the viewport tall with a floor of 500 px (less on a phone). It is the only size class shipped – there is no -small or -medium. For another height set div.style.height yourself, as the examples on this site do.

Prose

vm-swatch

Tints a word to match a trace: <span class="vm-swatch vm-swatch-alt">red</span> gives red. The modifier is required; vm-swatch alone sets no color.

Modifier Token
vm-swatch-fn --vm-color-fn fn
vm-swatch-alt --vm-color-alt alt
vm-swatch-ok --vm-color-ok ok
vm-swatch-muted --vm-color-muted muted
vm-swatch-ink --vm-color-ink ink
vm-swatch-warn --vm-color-warn warn
vm-swatch-accent2 --vm-color-accent2 accent2
vm-swatch-accent3 --vm-color-accent3 accent3
vm-swatch-accent --vm-accent (the UI accent, not a palette color) accent

One modifier per palette color, matching the keys of VM.plotting.colors(), so a swatch in a sentence and the trace it describes always agree. There is no -halo: it is the page background, and a tint of it is invisible.

vm-invalid

A red border and tint on an <input> – for a field whose value failed to parse. Nothing in the library adds it; a page toggles it from the cell that validates:

viewof x0 = {
  const view = Inputs.text({label: "x₀", value: "1"})
  view.addEventListener("input", () => {
    const ok = VM.expressions.makeNumber(math, view.value) !== null
    view.querySelector("input").classList.toggle("vm-invalid", !ok)
  })
  return view
}

It pairs with emptyState: the field says what is wrong, the chart says that something is.

Data attributes

data-vm-play="off"

On a range slider or any ancestor: opt out of the play button. Useful for a slider that isn’t a parameter sweep (a zoom level, a seed).

data-example-field="<name>"

On a viewof element, set by the cell that creates it, as a stable handle for applyExampleParams:

viewof fx = {
  const view = Inputs.text({label: "f(x)", value: "sin(x)"})
  view.dataset.exampleField = "fx"
  return view
}

The page’s fieldSelectors map is then {fx: '[data-example-field="fx"]', …}. Selectors rather than references, for a reason that entry explains.
