VM.ui

Controls: legend overlay, results table, readouts, URL state, example presets, slider playback

Most of what VM.ui does needs no call at all. Three modules are self-installing: they watch the page for the markup they enhance and attach themselves to it whenever it appears, including elements Observable Inputs recreates on a re-run.

Enhancement Attaches to Opt out
Slider playback – a play/pause button with speed and loop/bounce options every input[type="range"] inside .ojs-panel or .ojs-chart-controls data-vm-play="off" on the slider or any ancestor
Draggable legend – a grip that lets the reader move the floating legend, remembered per page every .ojs-legend-overlay inside .ojs-chart-block –
Slider fill – paints the filled part of the track in WebKit/Blink, which have no native progress pseudo-element every input[type="range"] –

The callable API is small: a legend that is also an Observable view, a table renderer, a row of stat readouts, a pair of URL-state helpers, the “try an example” helpers, and the pure arithmetic behind playback (exported for tests and for anyone building their own).

VM = window.VM
vmTheme = Generators.observe(notify => VM.plotting.onThemeChange(notify))
chartColors = VM.plotting.colors(vmTheme)

Legend

VM.ui.legendOverlay(items, options?)

A floating legend of clickable swatch+label rows that toggles which traces a chart shows, replacing Plotly’s built-in legend. It implements Observable Inputs’ view contract (a value property, an "input" event on change), so it slots into viewof exactly like an Inputs.checkbox:

viewof shown = VM.ui.legendOverlay([{label: "f(x)", color: chartColors.fn}, {label: "f'(x)", color: chartColors.alt}])

and shown is the array of checked labels. Put the cell inside the chart’s .ojs-chart-block: the CSS floats it over the chart’s top-left corner, and the draggable-legend module picks it up. For a Plotly figure with no controls, VM.plotting.plotWithLegend does this wiring in one cell; a simple figure is better drawn with Observable Plot and a static key.

Parameter Type Default Description
items {label, color}[] Rows, in display order.
options.value string[] every label The initially checked labels.

Returns an HTMLDivElement (div.ojs-legend-overlay) with:

  • a value accessor – getter returns the checked labels in items order (string[]); the setter accepts any iterable (null clears all) and re-renders
  • a bubbling "input" event on each user toggle (click, Enter, Space) – not on a programmatic value set, matching Observable Inputs and the set-then-dispatch protocol applyExampleParams uses

It uses only DOM APIs – no htl or Inputs dependency – so it works on a plain page too.

viewof legendShown = VM.ui.legendOverlay([
  {label: "sin", color: chartColors.fn},
  {label: "cos", color: chartColors.alt},
  {label: "sin·cos", color: chartColors.ok}
])
{
  const xs = [], s = [], c = [], sc = []
  for (let i = 0; i <= 200; i++) { const x = -Math.PI + 2 * Math.PI * i / 200; xs.push(x); s.push(Math.sin(x)); c.push(Math.cos(x)); sc.push(Math.sin(x) * Math.cos(x)) }
  const data = [
    {name: "sin", x: xs, y: s, line: {color: chartColors.fn}},
    {name: "cos", x: xs, y: c, line: {color: chartColors.alt}},
    {name: "sin·cos", x: xs, y: sc, line: {color: chartColors.ok}}
  ]
  for (const trace of data) trace.visible = legendShown.includes(trace.name) ? true : "legendonly"
  const div = document.createElement("div")
  div.style.height = "300px"
  Plotly.newPlot(div, data, {showlegend: false, xaxis: {title: "x"}})
  VM.plotting.autoResize(div)
  return div
}
legendShown

Try dragging the legend by its grip (appears on hover), then reload – the position is remembered.

VM.ui.staticKey(items, options?)

A simple figure – a convergence or error plot, which the reader reads rather than explores – is drawn with Observable Plot, not Plotly (see Plotly or Observable Plot), and its series are named by a key under it rather than by a floating legend. The key sits in normal flow, so it never covers the curve, wraps when the row is full, and stays visible at every width. Each swatch is drawn like its mark – a dashed line dashed, a band shaded, a dot a dot – so series that share a color stay apart. Return the chart and the key from one cell, in one div:

{
  const rows = []
  for (let i = 0; i <= 200; i++) {
    const x = -Math.PI + 2 * Math.PI * i / 200
    rows.push({x, sin: Math.sin(x), cos: Math.cos(x), lo: Math.sin(x) - 0.3, hi: Math.sin(x) + 0.3})
  }
  const dots = rows.filter((_, i) => i % 20 === 0)
  const chart = Plot.plot(VM.plotting.plotOptions({
    width: 640, height: 300,
    x: {label: "x"}, y: {label: null},
    marks: [
      Plot.areaY(rows, {x: "x", y1: "lo", y2: "hi", fill: chartColors.fn, fillOpacity: 0.2}),
      Plot.line(rows, {x: "x", y: "sin", stroke: chartColors.fn, strokeWidth: 2}),
      Plot.line(rows, {x: "x", y: "cos", stroke: chartColors.alt, strokeWidth: 2, strokeDasharray: "6,4"}),
      Plot.dot(dots, {x: "x", y: "cos", fill: chartColors.alt, r: 3})
    ]
  }))
  const key = VM.ui.staticKey([
    {label: "sin ± 0.3", marks: [
      {mark: "area", fill: chartColors.fn, fillOpacity: 0.2},
      {mark: "line", stroke: chartColors.fn, strokeWidth: 2}
    ]},
    {label: "cos", stroke: chartColors.alt, strokeWidth: 2, strokeDasharray: "6,4"},
    {label: "samples", mark: "dot", fill: chartColors.alt, r: 3}
  ])
  const figure = document.createElement("div")
  figure.append(chart, key)   // append(key, chart) puts the key above
  return figure
}

An item’s options are the mark’s own, under Plot’s names and with Plot’s defaults, so they can be copied from the Plot.line(...) call.

Parameter Type Default Description
items object[] Rows, in order: {label, mark, ...options}, or {label, marks: [{mark, ...options}, ...]} for a swatch of several marks drawn in order (a band with its mean line, a line with dots).
items[].label string The series name.
items[].mark "line", "area", "dot" "line" A horizontal line, a filled rectangle, or a dot in the middle.
items[].stroke string "currentColor" for a line or an unfilled dot; none for an area or a filled dot Line color; a dot’s or area’s outline.
items[].strokeWidth number 1.5
items[].strokeDasharray string e.g. "6,4".
items[].strokeOpacity number
items[].fill string "currentColor" for an area; none (hollow) for a dot
items[].fillOpacity number
items[].r number 3 A dot’s radius; a bigger dot makes its swatch taller.
options.swatchWidth number 28 Swatch width in px – two periods of a "6,4" dash.

Returns a div.vm-static-key with one span.vm-static-key-item per item: an aria-hidden SVG swatch, then the label. Colors are used as given, so take them from chartColors and the cell redraws the key with the chart on a theme toggle. A mark other than the three throws a TypeError. The key doesn’t toggle anything.

Draggable legend

The grip on the legend above is added by a self-installing module. It clamps the panel to the chart block, re-clamps on resize and fullscreen, supports the keyboard (arrows move 10 px, Shift+arrow 50 px, Home resets) and double-click to reset, and persists the offset in localStorage. It deliberately does not touch .ojs-chart-controls, which sits in normal flow above the chart and has nothing to be dragged clear of. The two pure helpers behind it:

VM.ui.clampOverlayOffset({…})

Clamps a proposed drag offset so no part of the panel leaves its container. Takes one object: {dx, dy, offsetLeft, offsetTop, width, height, containerWidth, containerHeight}. dx/dy are the proposed offset; offsetLeft/offsetTop the panel’s layout position (transforms don’t affect layout, so they stay a fixed reference); width/height the panel’s size; containerWidth/containerHeight the block’s.

Returns {dx, dy}. A panel larger than its container is pinned to the near edge rather than given a crossed range.

VM.ui.overlayStorageKey(pathname, role, id)

The localStorage key a dragged panel’s offset is kept under: `vml-overlay-pos:${pathname}:${role}:${id}`. The module uses location.pathname, "legend", and overlayChartId; the stored value is JSON.stringify({dx, dy}).

VM.ui.overlayStorageKey("/apps/newton-method/", "legend", "#newton")

VM.ui.overlayChartId({id, labels, occurrence})

Which chart a stored legend position belongs to: "#" + id when the .ojs-chart-block has an id, else the legend’s labels joined with | and #n for the n-th block on the page with the same labels. Stable across visits however the page’s cells render – give a block an id to be certain.

[VM.ui.overlayChartId({id: "newton", labels: ["f"], occurrence: 0}), VM.ui.overlayChartId({id: "", labels: ["f", "tangent"], occurrence: 1})]

Table

VM.ui.renderTable({headers, rows, csvHeaders?, filename?})

A compact, horizontally scrollable results table with a “Download csv” link above it.

Parameter Type Default Description
html function No longer used: the table is built with DOM calls, which is much faster for a long table. Still accepted, so existing calls keep working.
headers Array Header cells. May be DOM nodes (a tex template’s output) as well as strings.
rows Array[] Body rows of strings, numbers or DOM nodes. The first column is centered, the rest right-aligned, all nowrap.
csvHeaders string[] headers Plain-text labels for the download. Without them a node header’s textContent is used, which reads oddly for typeset math.
filename string "iteration-table.csv" The download’s name.

Returns one fragment: <div class="ojs-table-toolbar"> (the link) then <div class="ojs-table-container"><table class="table table-sm table-bordered small">. The table classes are Bootstrap’s, so it inherits the Quarto theme’s table styling.

{
  const rows = []
  let x = 1
  for (let n = 0; n < 6; n++) { rows.push([n, x.toFixed(10), Math.abs(x - Math.SQRT2).toExponential(2)]); x = x - (x * x - 2) / (2 * x) }
  return VM.ui.renderTable({headers: ["n", tex`x_n`, tex`|x_n - \sqrt2|`], rows, csvHeaders: ["n", "x_n", "error"], filename: "newton-sqrt2.csv"})
}

Readouts

VM.ui.statRow(items)

A row of small label-over-value tiles, for the handful of numbers a Monte Carlo page reports on every slider move – an estimate, its standard error, an acceptance rate. Put it between the controls panel and the chart, or inside the page’s .ojs-chart-block after the chart cell, where it sits under the chart and stays visible when the chart is fullscreened (lined up with the letterboxed chart, like the slider bar). The tiles share the panel’s surface and border, show values in the monospace face so digits don’t jitter, and wrap onto more rows on a narrow screen. Each tile is at most 14rem wide, so a row of one or two doesn’t stretch across the page.

Parameter Type Description
items {label, value, title?}[] One tile each, in order. A number value is shown as-is, so format it first. title becomes the tile’s tooltip, for a definition too long for the label.

Returns <div class="vm-stat-row"> holding one <div class="vm-stat"> per item, each a .vm-stat-label above a .vm-stat-value.

VM.ui.statRow([
  {label: "estimate", value: (3.14159).toFixed(4)},
  {label: "std. error", value: (0.0123).toFixed(4)},
  {label: "acceptance", value: "43%", title: "fraction of proposals accepted"}
])

URL state

A page can make every input shareable: read each default from the query string, and write the current values back as they change, so the address bar is always a link to what the reader sees.

viewof n = Inputs.range([10, 5000], {label: "n", step: 10, value: VM.ui.urlParam("pi_n", 1000)})
VM.ui.syncUrlParams({pi_n: [n, 1000], pi_seed: [seed, 1]})

Give each app’s keys a prefix when several share one page. A key at its default is removed rather than written, so a reader who never touches an app doesn’t find its parameters appended to the URL.

VM.ui.urlParam(key, fallback, opts?)

Reads one query-string parameter, typed like its fallback.

Parameter Type Default Description
key string The parameter name.
fallback number \| string \| boolean Returned when the key is absent or doesn’t parse. A number fallback parses with Number (a blank or non-finite result falls back); a boolean fallback accepts "1"/"true" and "0"/"false"; a string fallback returns the raw value.
opts.search string location.search The query string to read.

Returns a value of the fallback’s type.

[VM.ui.urlParam("n", 10, {search: "?n=250"}), VM.ui.urlParam("n", 10, {search: "?n=abc"}), VM.ui.urlParam("lazy", false, {search: "?lazy=1"})]

VM.ui.syncUrlParams(entries, opts?)

Writes inputs into the current URL’s query string with history.replaceState – no navigation, no history entry – leaving every other key alone (another app’s, or embed) and keeping history.state. Call it on every input event: an unchanged query is never written, and writes are spaced at least 250 ms apart (the first at once, the last always lands), which keeps a slider drag or a playback sweep under the browsers’ history-API rate limits – Safari throws past 100 calls in 10 seconds.

Parameter Type Default Description
entries {key: [value, default]} A key whose value equals its default (compared as strings) is removed rather than written.
opts.search string location.search Start from this query string instead. When given, the URL is not touched and only the result is returned.

Returns string, the new query string without the leading ? ("" when nothing is left).

VM.ui.syncUrlParams({pi_n: [5000, 1000], pi_seed: [1, 1]}, {search: "?pi_seed=3&embed=1"})

Example presets

VM.ui.applyExampleParams(fieldSelectors, params, triggerEl)

Applies an example’s parameter values to the page’s viewof fields, then clicks the page’s own “plot”/“run” button so the normal commit flow runs – no reload, no scroll jump. This is what a “Try an example” dropdown calls.

Parameter Type Description
fieldSelectors {paramKey: cssSelector} Plain strings, looked up fresh with document.querySelector each time – e.g. {fx: '[data-example-field="fx"]'}. Tag each targetable field with a stable data-example-field attribute in the cell that owns it.
params {paramKey: value} Applied in insertion order with a 100 ms wait after each (including the last), so a field whose bounds depend on an earlier one sees its freshly recreated view. Order upstream fields first. Keys with no selector, or whose element isn’t on the page, are skipped.
triggerEl Element An element containing the <button> to click at the end. Must not be null (throws); the click is skipped if it holds no button.

Returns Promise<void>.

Two rules that come from how Observable’s runtime behaves, both learned the hard way:

ImportantPass selectors, not viewof references

A cell that references a view whose identity is reactively recreated – a step slider capped by a “max” field – becomes reactive on it. Since this function is what changes that upstream field, a version taking direct references re-triggers itself in a loop with no natural end. A querySelector at the moment of use carries no reactive dependency.

ImportantCall it from a plain DOM listener, never from a cell reactive on a <select>

A native <select> fires both input and change per selection, so a reactive cell runs twice, and two overlapping calls race – observed corrupting a field’s final value when the second cascade landed after the first. Attach one listener to a stable element instead. The starter’s try-an-example.qmd shows the full wiring.

VM.ui.syncExampleSelect(selectView, examples, fieldSelectors)

Points the “Try an example” dropdown at whichever example the page’s fields currently hold, so it never names an example the chart isn’t showing. Call it from a cell that reads every example field’s value, so it re-runs whenever one changes.

Parameter Type Description
selectView Element The viewof exampleSelect element. Its options must be [null, ...examples].
examples Array<{title, params}> The page’s presets.
fieldSelectors {paramKey: cssSelector} The same object passed to applyExampleParams.

Returns nothing. It sets the view’s value without dispatching an event, so nothing downstream re-runs and the page’s "change" listener doesn’t re-apply the example.

The leading null option (format it as “Custom inputs”) is disabled and hidden in the list on every call, so it shows only when no example matches (a shared link with its own inputs, or a field the reader has edited) and can’t be picked. Because of that, a page’s default inputs should equal one of its examples. While an applyExampleParams call is in flight the function does nothing, since the fields pass through half-applied states that match no example.

syncExampleFromFields = {
  fText; x0Text; maxText   // every example field, so this re-runs when any changes
  VM.ui.syncExampleSelect(viewof exampleSelect, examples, exampleFieldSelectors)
}

VM.ui.findMatchingExample(examples, values)

The matcher behind syncExampleSelect: returns the first example whose params all equal the given field values, or null.

Parameter Type Description
examples Array<{title, params}> Checked in order; the first match wins.
values {paramKey: currentValue} A param key with no entry here (a field this page doesn’t have) is ignored.

Returns the matching example object, or null when none matches or when no param key had a value to compare. The comparison is loose: scalars compare as trimmed strings (a URL-style "20" equals a slider’s 20), arrays compare element by element in order, and plain objects key by key.

VM.ui.findMatchingExample(
  [{title: "Square root of 2", params: {f: "x^2 - 2", x0: "1"}},
   {title: "Cube root of 5", params: {f: "x^3 - 5", x0: "2"}}],
  {f: "x^3 - 5", x0: 2}
)

Slider playback

Every range slider inside an .ojs-panel or .ojs-chart-controls gets a play/pause button and a small caret that opens a popover of speed presets (¼× – 4×) and a mode (Once / Loop / Bounce). Playback is requestAnimationFrame-driven, so the motion is smooth rather than a stepped jump; it stops when the reader grabs the slider, when the tab is hidden, when a re-run detaches the slider, and at the end of a Once sweep (the button becomes a replay glyph). At most one sweep runs per page.

viewof playDemo = Inputs.range([0, 2 * Math.PI], {label: "phase (press ▶)", step: 0.05, value: 0})
{
  const xs = [], ys = []
  for (let i = 0; i <= 300; i++) { const x = 4 * Math.PI * i / 300; xs.push(x); ys.push(Math.sin(x - playDemo)) }
  const div = document.createElement("div")
  div.style.height = "220px"
  Plotly.newPlot(div, [{x: xs, y: ys, line: {color: chartColors.fn, width: 2.5}}], {showlegend: false, yaxis: {range: [-1.2, 1.2]}, margin: {t: 8}})
  VM.plotting.autoResize(div)
  return div
}

The chosen speed and mode are a viewing preference, shared by every slider on the site and stored in localStorage["vm-playback"] as {speed, mode} – deliberately not URL-synced like the page’s inputs, since they’re not part of the computation a shared link reproduces.

The sweep’s length scales with the slider’s own stop count – about 350 ms per stop, clamped to 2–10 s – which is what lets the module enhance every slider with no per-page tuning. A page opts a slider out with data-vm-play="off" on the input or an ancestor:

{
  const wrap = document.createElement("div")
  wrap.dataset.vmPlay = "off"
  wrap.appendChild(Inputs.range([0, 10], {label: "data-vm-play=\"off\": no play button", step: 1, value: 3}))
  return wrap
}
Inputs.range([0, 10], {label: "a sibling without it", step: 1, value: 3})
NoteWhy the popover is a native [popover]

It renders in the browser’s top layer. Quarto wraps every OJS output in .cell-output-display with overflow: auto, which clips any descendant that escapes its box – a panel opening above a 37 px cell was cut to a sliver. No z-index fixes a clip; only leaving it does, and the top layer is outside every ancestor’s clip. This applies to any floating UI inside any OJS cell: reach for [popover], not a nested absolute box.

VM.ui.playbackDuration({…})

Takes one object: {min, max, step, speed}. Total length of one end-to-end sweep, in ms: 350 ms × stops, clamped to [2000, 10000], divided by speed. A non-finite or non-positive step (a slider with step="any") counts as 100 stops; a non-finite or non-positive speed as 1.

Returns number; 0 when the slider can’t be swept (max ≤ min, or a non-finite bound).

[VM.ui.playbackDuration({min: 0, max: 10, step: 1, speed: 1}), VM.ui.playbackDuration({min: 0, max: 100, step: 1, speed: 2}), VM.ui.playbackDuration({min: 0, max: 0, step: 1, speed: 1})]

VM.ui.playbackFrame({…})

Takes one object: {min, max, step, elapsed, duration, mode, start}. Where the thumb should be after elapsed ms of a sweep of length duration that began at start: a fraction of the track going up, or for a bounce 1..2 on the way down (2 − f is fraction f heading back), which is how a speed change mid-bounce keeps the direction. mode is "once", "loop" (sawtooth) or "bounce" (triangle wave); anything else behaves as "once".

Returns {value, direction, done} – value snapped to the step grid (by whole-step count from min, then trimmed to 12 significant digits, then clamped into [min, max]); direction is −1 only on a bounce’s return leg; done is true once a "once" sweep reaches the end, and for any degenerate input.

VM.ui.playbackFrame({min: 0, max: 10, step: 0.5, elapsed: 750, duration: 3000, mode: "bounce", start: 0})

VM.ui.playbackTweenMs

A number, not a function: the chart transition length VM.plotting.layout() should use right now. 0 while no sweep is running; during one, 90% of the gap between consecutive slider values, capped at 300 ms, so each tween settles just before the next value arrives instead of a flat 300 ms overrunning a faster gap and leaving the chart permanently mid-tween. Read it if you build your own layout; don’t set it.

Watching for new elements

OJS creates – and recreates – inputs, legends and figures long after the page loads, so mathviz’s self-installing pieces (the play buttons, the slider track fill, the draggable legend, the SVG fullscreen button) wait for them with one shared watcher instead of a MutationObserver each.

VM.ui.whenAdded(selector, enhance, opts?)

Calls enhance on every element matching selector now (at DOMContentLoaded if the page is still loading) and again whenever the DOM changes, with at most one query per selector per animation frame – however many nodes a Plotly redraw adds. The pass runs before the frame is painted, so an enhancement never shows up a frame late. enhance sees the same element on every pass, so it must be idempotent: mark what it did (a data-* attribute) and return early.

Parameter Type Description
selector string A CSS selector, queried over the whole document.
enhance (element) => void
opts.beforeScan () => void (optional) Runs before each pass, e.g. to drop state kept for elements that have left the page.

Returns () => void, which stops watching. A no-op outside a browser.

VM.ui.sliderBounds(input)

A range input’s {min, max, step} as numbers, read the way the browser reads them: min/max default to 0/100 when absent or unparsable, and step is NaN for step="any", a missing step, or one that doesn’t parse. The slider track fill and slider playback both use it.

[VM.ui.sliderBounds({min: "2", max: "8", step: "0.5"}), VM.ui.sliderBounds({min: "", max: "", step: "any"})]
