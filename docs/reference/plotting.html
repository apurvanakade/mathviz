VM.plotting

The chart theme, draggable points, the Plotly patch, and the fullscreen buttons

Everything a chart needs to look like part of the page: one theme read live from the --vm-* tokens, applied to Plotly and Observable Plot alike, and following the light/dark toggle the moment it flips.

Two things to hold onto:

  1. Every function reads the tokens at call time, from document.body. Call colors() inside the cell that builds traces; never cache the result in a module-level constant. (Why body: the dark tokens are declared on a selector that matches <body>, so <html> reports the light values even in dark mode – the origin of a white tooltip on a dark chart.)
  2. On a page rendered through the extension, the Plotly patch is already installed. Plotly.newPlot(div, data, {xaxis: {title: "x"}}, {}) gets the full theme, tooltip style, pan-by-default and the shared modebar with no VM.plotting.* call at all. The theme functions are for what the patch can’t reach: the colors you bake into traces, and Observable Plot.
VM = window.VM
vmTheme = Generators.observe(notify => VM.plotting.onThemeChange(notify))
chartColors = VM.plotting.colors(vmTheme)

Palette

VM.plotting.colors()

A fresh snapshot of the chart palette for whichever theme is active right now, read from the --vm-color-<name> tokens. Keyed by role, not hue, so a page reads colors.fn rather than repeating "#2563eb".

Key Role on a chart Light default Dark default
fn the function itself, the primary trace #2563eb #8ab4ff
alt an alternate or reference trace #dc2626 #f87171
ok a converged / correct / “good” marker #16a34a #4ade80
muted de-emphasized data, history #94a3b8 #7d8aa3
ink strokes and labels that should read as text #111827 #c9cedb
warn a warning, a diverging iterate #f59e0b #fbbf24
accent2 a third series #9333ea #c084fc
accent3 a fourth series #0d9488 #2dd4bf
halo the ring around a marker – white on light, the page background on dark. Use it instead of "white". #ffffff #16181b

Returns {fn, alt, ok, muted, ink, warn, accent2, accent3, halo} as CSS color strings. Falls back to the light hexes when no stylesheet is loaded.

Any argument is ignored. The idiom VM.plotting.colors(vmTheme) exists purely to make the OJS cell depend on vmTheme – see onThemeChange.

chartColors
{
  const row = document.createElement("div")
  row.style.cssText = "display:flex;gap:.5rem;flex-wrap:wrap"
  for (const name of Object.keys(chartColors)) {
    const chip = document.createElement("div")
    chip.style.cssText = `width:5.5rem;padding:.4rem .5rem;border-radius:6px;border:1px solid var(--vm-border);background:${VM.plotting.alpha(chartColors[name], 0.25)};font:12px var(--vm-font-sans)`
    chip.innerHTML = `<span style="display:inline-block;width:.8rem;height:.8rem;border-radius:50%;background:${chartColors[name]};vertical-align:-1px;margin-right:.3rem"></span>${name}`
    row.appendChild(chip)
  }
  return row
}

VM.plotting.colorway()

The trace color cycle – colors() in role order minus halo, so a trace Plotly or Plot colors automatically never lands on the background color. Already set on layout() and plotOptions().

Returns string[]: [fn, alt, ok, muted, ink, warn, accent2, accent3].

VM.plotting.alpha(token, opacity)

The same hue as a palette token (or any color string) at a given opacity, for a translucent fill that pairs with a solid stroke. An rgba(...) literal stays light-mode-colored after a toggle while its own stroke lightens, so fill and stroke drift apart; this doesn’t.

Parameter Type Description
token string A palette role ("fn", "ok", …) resolved through colors(), or any CSS color. Hex (3, 4, 6 or 8 digits) and rgb()/rgba() are parsed directly; anything else (hsl(), oklch(), a named color) is resolved by the browser.
opacity number 0..1; not clamped. Replaces any alpha the color had.

Returns "rgba(r, g, b, opacity)". The input comes back unchanged only when it isn’t a color at all (or, outside a browser, is neither hex nor rgb()), or is fully transparent.

[VM.plotting.alpha("ok", 0.2), VM.plotting.alpha("#ff0000", 0.5), VM.plotting.alpha("rebeccapurple", 0.5)]

VM.plotting.subscript(value)

Replaces each digit with its Unicode subscript, for iteration labels in Plotly trace text – which is plain text with no markup, so "x_0" renders with a literal underscore.

Returns string; non-digit characters pass through.

["x" + VM.plotting.subscript(0), "x" + VM.plotting.subscript(12), VM.plotting.subscript("n=3")]

Theme detection

VM.plotting.themeName()

Which theme is active right now, by testing the dark selector against <body> and then <html>.

Returns "light" | "dark" ("light" when there is no document).

vmTheme   // this cell re-runs on every toggle -- try it

VM.plotting.onThemeChange(callback)

Calls callback(themeName()) now, synchronously, and again after every real theme change. It observes class and data-bs-theme on both <body> and <html>, waits two animation frames (Quarto flips the class and swaps the stylesheet as separate steps, class first), and compares the theme name before calling – so unrelated body-class churn (a sidebar opening) fires nothing.

Parameter Type Description
callback (theme: "light" \| "dark") => void

Returns () => void, a teardown that disconnects the observer (a no-op when there’s no document.body or MutationObserver; the initial call still happens).

The shape is exactly what Generators.observe wants, which gives the two-line pattern every chart page needs:

vmTheme = Generators.observe(notify => VM.plotting.onThemeChange(notify))
chartColors = VM.plotting.colors(vmTheme)

Now any cell that reads chartColors re-runs on a toggle. This is what makes trace colors follow the theme. Chart chrome (axes, grid, tooltip) is re-themed for you by a relayout the patch performs, but a color you baked into a trace is a value the page chose, and only re-running the cell changes it. colors() ignores its argument; colors(vmTheme) is written that way purely so that chartColors depends on vmTheme in Observable’s dependency graph.

VM.plotting.configure(overrides?)

Adjusts the module’s settings. The only setting is darkSelector: the selector list that means “dark mode”, tested against <body> and <html>. Default:

body.quarto-dark, html[data-bs-theme="dark"], body[data-bs-theme="dark"], html.vm-dark, body.vm-dark

A site whose toggle uses none of these calls VM.plotting.configure({darkSelector: ".my-dark"}) once at load, and declares its dark --vm-* tokens under that same selector. Keep the selectors root-scoped (html/body); an unscoped [data-bs-theme="dark"] matches Quarto’s <nav> and leaks the dark palette into the navbar.

Parameter Type Description
overrides {darkSelector?: string} Merged in when it’s an object; anything else is ignored. Keys are not validated.

Returns a copy of the settings now in effect.

Building a chart

VM.plotting.layout(overrides?)

The shared Plotly layout, themed from the live tokens:

  • transparent paper_bgcolor / plot_bgcolor, so the page’s own background shows through (no #E5ECF6 plate, no white box in dark mode)
  • font in --vm-font-sans, --vm-text; axes, ticks, gridlines in --vm-text-soft / --vm-border / --vm-grid, automargin: true – on xaxis/yaxis and on every further subplot the overrides name (xaxis2, yaxis3, scene, polar, ternary, …; see subplotKeys)
  • colorway(), hoverLabel(), themed modebar colors, textfont for trace labels
  • a transition of 300 ms cubic-in-out (0 under prefers-reduced-motion; while a slider playback sweep runs, shortened to the gap between values so the tween lands before the next one arrives)
  • small non-zero margin ({l: 8, r: 12, t: 12, b: 8}) that automargin grows as needed
Parameter Type Description
overrides object (optional) Deep-merged on top, so {xaxis: {title: "x", range: [0, 1]}} extends the shared axis chrome rather than replacing it. Arrays and primitives replace wholesale.

Returns a Plotly layout object.

WarningDon’t pass margin: {l: 0, r: 0, t: 0, b: 0}

It was a common convention and it defeats automargin: the rotated y-title and tick labels end up jammed against the container edge.

With the patch installed this is merged under every newPlot/react layout automatically. Calling it explicitly is harmless and makes the dependency visible.

VM.plotting.config(overrides?)

{responsive: true, displaylogo: false}, deep-merged with overrides. The patch also applies this and then sets the modebar button list on top.

VM.plotting.hoverLabel()

The themed tooltip style: --vm-surface background, --vm-border border, left-aligned, 12 px --vm-font-sans in --vm-text.

It has to be set on each trace, not only the layout – Plotly derives a trace’s tooltip background from that trace’s own color unless the trace sets hoverlabel itself, so a layout-level default never actually shows. The patch injects it onto every trace that doesn’t set one. Call it yourself only for a chart built outside the patch.

VM.plotting.emptyState(message)

A centered message for an empty plot area, as an annotations array. Use it whenever the page’s computation bailed out; without it an unparseable input draws an empty grid indistinguishable from a valid-but-empty result.

annotations: f ? [] : VM.plotting.emptyState("Couldn't parse that expression")

Returns a one-element Plotly annotations array at paper coordinates (0.5, 0.5) in --vm-text-soft.

VM.plotting.autoResize(div)

Keeps a graph div sized to its container, and stops once the div leaves the document. Every chart built detached (the usual OJS pattern: create a div, Plotly.newPlot into it, return it) needs this, because Plotly measures 0×0 at newPlot time. A bare ResizeObserver outlives its div and throws "Resize must be passed a displayed plot div element." once a re-run replaces it; this one disconnects itself.

Returns the ResizeObserver, or null where ResizeObserver doesn’t exist. Skips resizing while the div is hidden (display: none) and is safe when Plotly isn’t loaded.

A chart with a scaleanchor axis is refitted to the reader’s view after each resize (fitView), so resizing it never zooms it out.

VM.plotting.persistentPlot(opts?)

The draw-once, redraw-in-place chart closure most pages write by hand, packaged. Call it once in a cell that depends on nothing reactive, and call the function it returns from the cell that builds the traces:

mainPlot = VM.plotting.persistentPlot()
mainPlot(traces, VM.plotting.layout({xaxis: {title: {text: "x"}}}))

The first call creates the div, Plotly.newPlots into it and hands it to autoResize. Every later call Plotly.reacts into the same div, which (with uirevision) keeps the reader’s zoom and pan while a slider moves.

Parameter Type Default Description
opts.className string "plotly-box-large" Class of the graph div.
opts.height string Inline CSS height, for a secondary chart that shouldn’t take the main chart’s box, e.g. "320px". Sets min-height to the same value, so it holds below the box’s own 500px minimum.

Returns (data, layout, config?) => HTMLElement, which draws or redraws and returns the same div every time. config defaults to config(). The function’s read-only div property is that div (null before the first draw), for code that needs the chart without redrawing it. Needs window.Plotly.

VM.plotting.persistentPlot3d(opts?)

persistentPlot for 3-D traces (surface, scatter3d, mesh3d, …). Use it for every 3-D chart, in exactly the same way:

surfacePlot = VM.plotting.persistentPlot3d({height: "420px"})
surfacePlot([{type: "surface", z}], {scene: {zaxis: {title: {text: "density"}}}})

Dragging rotates the scene about its vertical axis (turntable, Plotly’s own 3-D default), the scroll wheel zooms, and the modebar carries the 3-D tools. The scene’s axes follow the theme, including on a dark-mode toggle. All of that comes from the Plotly patch, which treats a chart as 3-D when its layout has a scene. A 3-D trace draws without one, though, and would then pan on drag with the 2-D buttons. This closure always passes a scene, keeping the page’s own (camera, axis titles, dragmode, …).

Parameter Type Default Description
opts.className string "plotly-box-large" As for persistentPlot.
opts.height string As for persistentPlot.

Returns (data, layout, config?) => HTMLElement, with a div property, as for persistentPlot. Needs window.Plotly.

VM.plotting.plotWithLegend(plot, data, layout)

For a figure with no controls of its own: draws the chart with a VM.ui.legendOverlay over it instead of Plotly’s legend, and returns both wrapped in an .ojs-chart-block, in one cell. Clicking a row hides or shows every trace of that name (as visible: "legendonly", so every trace keeps its index and its colorway color); unnamed traces and showlegend: false ones are always drawn. Hiding a trace never rescales the chart or moves its grid: the first click pins every axis at the range it had with all traces shown (see lockedAxes), and a new call – new data, a theme toggle – starts unpinned again. It is the three-cell viewof wiring the legend’s reference shows, for pages with many such figures.

figPlot = VM.plotting.persistentPlot({height: "360px"})
VM.plotting.plotWithLegend(figPlot, traces, {xaxis: {title: "n"}})
Parameter Type Description
plot (data, layout) => HTMLElement A chart function, such as persistentPlot()’s return value.
data Object[] Plotly traces.
layout Object Plotly layout; showlegend is forced false.

Returns the div.ojs-chart-block: a div holding the legend, then the one plot returned. With no named traces it holds only the chart. The legend hides below a 600px-wide chart, like every overlay legend, and then every trace is drawn. A simple figure is better drawn with Observable Plot and a static key, which stays visible at every width (see Plotly or Observable Plot).

VM.plotting.legendItems(data, colorway?)

The legend rows plotWithLegend builds: {label, color} for each trace with a name and without showlegend: false, in trace order, one row per name. The color is the trace’s line.color, else its marker.color (when a single color), else its fillcolor, else the colorway color Plotly gives it – counted the way Plotly counts, skipping traces set visible: false. colorway defaults to colorway(); plotWithLegend passes the layout’s own when it has one. A trace colored per point (a marker.color array) with no line color gets no swatch color.

VM.plotting.lockedAxes(fullLayout, layout)

The layout overrides plotWithLegend uses to pin a chart’s axes: {xaxis: {...layout.xaxis, range, autorange: false}, ...} for every cartesian axis (xaxis, yaxis, xaxis2, …) in a drawn div’s _fullLayout, at the range Plotly resolved – already in log units on a log axis, which is what range expects there. An axis with a range in the page’s own layout is left out, and so is everything that isn’t a cartesian axis (a 3-D scene). {} when fullLayout is missing.

VM.plotting.paddedRange(values, opts?)

A {lo, hi} axis range covering an array of values with some breathing room.

Parameter Type Default Description
values number[] Non-finite entries are ignored.
opts.emptyRange [number, number] [-1, 1] Returned when values has no finite entry.
opts.relativePadding number 0.1 Padding as a fraction of the span hi − lo.
opts.minPadding number 0.5 Floor on the padding, for small or zero spans (every value identical).

Returns {lo, hi}.

[VM.plotting.paddedRange([1, 2, 3, NaN, 10]), VM.plotting.paddedRange([5, 5, 5]), VM.plotting.paddedRange([])]

VM.plotting.plotOptions(overrides?)

The Observable Plot equivalent of layout(): same font, grid color and colorway. It themes a simple figure drawn with Observable Plot (see Plotly or Observable Plot), so it reads as the same chart system as the page’s Plotly app charts.

Parameter Type Description
overrides object (optional) Deep-merged on top. If it names an x or y scale without a stroke, that axis is stroked in --vm-border; scales it doesn’t name are left for Plot to default.

Returns options for Plot.plot(...).

{
  const pts = []
  for (let i = 0; i <= 40; i++) pts.push({x: i / 4, y: Math.exp(-i / 16) * Math.cos(i / 3)})
  return Plot.plot(VM.plotting.plotOptions({
    height: 220, x: {label: "t"}, y: {label: "damped"},
    marks: [Plot.line(pts, {x: "x", y: "y", stroke: chartColors.fn, strokeWidth: 2}), Plot.ruleY([0])]
  }))
}

VM.plotting.themePatch(opts?)

The theme-dependent style attributes as a flat, dotted-path object for Plotly.relayout – {"xaxis.gridcolor": …, "hoverlabel.bgcolor": …, colorway: […]}. relayout replaces whatever attribute each key names wholesale, so a nested {xaxis: {...}} would wipe the page’s own xaxis.title/range; dotted keys patch only the one sub-property. The patch runs this over every live .js-plotly-plot on each theme flip. A page shouldn’t need to call it.

Parameter Type Default Description
opts.layout object The chart’s layout or _fullLayout. Every subplot it names (subplotKeys) is patched too: yaxis2, scene, polar, … A subplot the chart doesn’t have is never added – relayout-ing a scene.* key would add a scene. The patch passes each chart’s _fullLayout.
opts.scene boolean false Also patch scene, for a caller not passing opts.layout.

Returns every color layout() sets, at its dotted path – 25 keys for a chart with only xaxis/yaxis, 18 more per scene.

VM.plotting.subplotKeys(layout)

The subplot keys a Plotly layout names, grouped by kind – what the theme, the zoom buttons and the axis-pinning helpers iterate over.

Returns {cartesian, scene, polar, ternary}, each a string[] of keys in the layout’s order (cartesian: ["xaxis", "yaxis", "yaxis2"]); all empty for a missing layout.

VM.plotting.subplotKeys({xaxis: {}, yaxis2: {overlaying: "y"}, polar: {}, title: {text: "t"}})

Draggable points

VM.plotting.draggablePoints(plot, opts)

Points on a Plotly chart that the reader drags, as an Observable view: value is {x, y} when you give it one point and [{x, y}, ...] when you give it an array, and an "input" event fires on every move, so other cells react to the points the way they react to a slider. Call it in a viewof cell that depends on nothing reactive, and draw the traces from a separate cell with the same chart function – a theme toggle then redraws the traces without re-running the viewof, which would reset the points:

trianglePlot = VM.plotting.persistentPlot({height: "420px"})
viewof corners = VM.plotting.draggablePoints(trianglePlot, {
  value: [{x: 0, y: 0}, {x: 4, y: 0}, {x: 1, y: 3}],
  label: ["A", "B", "C"]
})
//| output: false
trianglePlot([{x: [...corners.map(p => p.x), corners[0].x], y: [...corners.map(p => p.y), corners[0].y]}],
  {xaxis: {range: [-1, 5], fixedrange: true}, yaxis: {range: [-1, 4], fixedrange: true}, dragmode: false},
  {...VM.plotting.config(), displayModeBar: false})

The paint cell is output: false because the chart is already on the page, in the viewof cell’s output. Fix both axes (fixedrange: true, dragmode: false) so a drag beside a point doesn’t pan the chart.

Each point is a focusable dot laid over the chart:

  • Mouse, pen, finger: press on the dot and drag. A touch that starts anywhere else on the chart still scrolls the page.
  • Keyboard: Tab to the dot; the arrow keys move it one step, Shift+arrow ten. Arrows move it the way the screen does, also on a reversed axis.
  • Screen readers: it is a role="slider" with aria-label from label and aria-valuetext from format, announced on every move.
  • Bounds: a point never leaves xBounds/yBounds (the visible ranges by default), even when the pointer leaves the chart.
  • Adding and removing (add, remove, for an array value): a press on the plot area away from the points adds one there (a tap, on a touch screen), and a double-click on a point, or Delete while it has focus, removes it.

Besides "input" on every move, the view fires "change" once each edit is finished – a drag released, an arrow-key move, a point added or removed – as a native range does when it lets go. Listen for it to redo work that shouldn’t run on every frame of a drag (a refitted axis, a recentered window):

committed = Generators.observe(notify => {
  const view = viewof corners
  const update = () => notify(view.value)
  view.addEventListener("change", update)
  update()
  return () => view.removeEventListener("change", update)
})
Parameter Type Default Description
plot Function \| HTMLElement A chart function such as persistentPlot()’s return value – its div is used as is, and only a chart not drawn yet is drawn once, empty, to get one – or a div Plotly has already drawn.
opts.value {x, y} or {x, y}[] required Starting position of one point, or of each of several. The view’s value keeps this shape.
opts.xBounds [lo, hi] the x-axis’s visible range Where the points may go, in data units.
opts.yBounds [lo, hi] the y-axis’s visible range
opts.constrain (point, index, points) => {x, y} Runs after the bounds on every move, with the points as they were before it (an array, even for one point); return where the point may go instead (inside a triangle, onto a curve, snapped to a grid). Its result isn’t clamped again.
opts.step {x?, y?} a hundredth of the bounds One arrow-key step, in data units.
opts.jump boolean false A press anywhere on the plot area moves the nearest point there: a mouse press keeps dragging it, a touch moves it on a tap (a swipe still scrolls). The plot area’s pointer events then go to the points, so Plotly’s hover and zoom stop working there.
opts.add boolean false A press on the plot area away from the points adds a point there: a mouse press keeps dragging it, a touch adds it on a tap. Takes the plot area’s pointer events as jump does, and can’t be combined with it. Needs an array value.
opts.remove boolean false A double-click on a point, or Delete/Backspace while it has focus, removes it; from the keyboard the focus moves to the next point. Needs an array value.
opts.minPoints number 0 remove stops at this many points.
opts.maxPoints number Infinity add stops at this many points.
opts.label string \| string[] "Point" Accessible names. For an array value, one string is numbered ("Point 1", …) and an array names each point. A name stays with its point when remove takes an earlier one; a point add puts past the array is numbered ("Point 4").
opts.format (point, index) => string "x 0.87, y 0.42" What a screen reader announces as the value. The default shows three significant digits.
opts.color string \| string[] "var(--vm-color-fn)" CSS color of the dots, or one per point; a color stays with its point across a remove, and an added point past the array takes the default. Use a var(--vm-color-*) token to follow the theme; a resolved color such as chartColors.fn would stay as it was.
opts.xaxis, opts.yaxis string "x", "y" The axes the points live on, for a chart with subplots ("x2", …).

Returns the chart’s div, with a value accessor (a copy, shaped like opts.value). Setting value moves the points without an "input" event, matching Observable Inputs; an array of another length rebuilds them. Calling it again on the same chart replaces the earlier points, so use one call, with several points, per chart. It fires "change" after each finished edit, as above. Throws a TypeError when opts.value is missing, plot gives no drawn Plotly div, add is combined with jump, or add/remove is given a single point.

The dots follow the chart through a resize, a theme toggle, fullscreen and a zoom, and are hidden while zoomed out of view. Their size is --vm-drag-point-size; the hit target around each is larger (2rem, 2.75rem on a touch screen). How they map pixels to data is in Internals.

One point, as in Buffon’s needle: drop is {x, y}. Drag the dot below, or click anywhere in the rectangle (jump: true):

viewof drop = VM.plotting.draggablePoints(dropPlot, {
  value: {x: 0.87, y: 0.42},
  xBounds: [0, Math.PI], yBounds: [0, 0.5], step: {x: 0.05, y: 0.01},
  jump: true, label: "Drop",
  format: p => `θ ${p.x.toFixed(2)}, d ${p.y.toFixed(2)}`
})
dropPlot = VM.plotting.persistentPlot({height: "320px"})
viewof drop = VM.plotting.draggablePoints(dropPlot, {
  value: {x: 0.87, y: 0.42},
  xBounds: [0, Math.PI], yBounds: [0, 0.5], step: {x: 0.05, y: 0.01},
  jump: true, label: "Drop",
  format: p => `θ ${p.x.toFixed(2)}, d ${p.y.toFixed(2)}`
})
dropPlot([
  {x: [0, Math.PI, Math.PI, 0, 0], y: [0, 0, 0.5, 0.5, 0], mode: "lines", fill: "toself",
    fillcolor: VM.plotting.alpha(chartColors.muted, 0.12), line: {color: chartColors.ink}, hoverinfo: "skip", showlegend: false}
], {
  xaxis: {title: {text: "θ"}, range: [-0.1, Math.PI + 0.1], fixedrange: true},
  yaxis: {title: {text: "d"}, range: [-0.02, 0.52], fixedrange: true},
  dragmode: false, hovermode: false
}, {...VM.plotting.config(), displayModeBar: false})

The Plotly patch

On load (and again on DOMContentLoaded) the library wraps Plotly.newPlot and Plotly.react. Every chart on the page then gets, with no per-page code:

  • layout() merged under the page’s layout

  • hoverLabel() on every trace that lacks a hoverlabel

  • dragmode: "pan", unless the page set its own

  • both call forms: newPlot(gd, data, layout, config) and newPlot(gd, {data, layout, config, frames}), with gd an element or its id

  • config() merged under the page’s config, then this modebar (a 3-D chart gets its own, below):

    Group Buttons
    1 download PNG
    2 box zoom, pan
    3 zoom in, zoom out (each step scales the visible span by 1.25×, not Plotly’s 2×, which overshoots when framing a curve), autoscale, reset
    4 fullscreen

    Box select and lasso are absent. The list is spelled out as config.modeBarButtons. A page that passes its own modeBarButtons keeps them untouched; modeBarButtonsToRemove and modeBarButtonsToAdd are applied to the shared list (the gentler zoom steps answer to "zoomIn2d"/"zoomOut2d"). The fullscreen button is left out where element fullscreen can’t work – iPhone Safari, an iframe without allow="fullscreen".

  • for a 3-D chart, meaning one whose layout has a scene (draw it with persistentPlot3d, which guarantees one): scene.dragmode: "turntable" unless the page set one, since a scene otherwise inherits "pan" and slides instead of rotating; themed scene axes; and the modebar download PNG | turntable rotation, orbit rotation, pan, zoom | reset camera | fullscreen

  • a relayout(themePatch({layout: gd._fullLayout})) on every theme flip, which re-themes every subplot the chart has

  • after each call, the listeners registered with keepListening put back – newPlot drops every listener on the div

The patch is idempotent and a silent no-op when Plotly isn’t on the page (mathviz: {plotly: false}).

Locked axes keep their view

A chart whose axes are locked to each other (yaxis: {scaleanchor: "x"}, so a circle looks round) needs nothing extra: the patch records the view and autoResize refits it. Plotly honours scaleanchor by widening one axis past the range asked for and writing the widened range back into the layout. Left alone, every resize would fit from the widened range and zoom the chart further out, and uirevision could never keep a reader’s zoom, because the page’s range never matches the widened one. The patch remembers the range the page asked for, replaced by the reader’s own once they zoom or pan, and fits from that instead. A redraw with the same uirevision keeps a view the reader moved; a double-click puts back the page’s range; the modebar’s autoscale hands the axis to Plotly. Charts without scaleanchor are untouched.

VM.plotting.trackView(gd, layout)

Records the view of a chart with a scaleanchor axis (see above). The patch calls it on every newPlot/react; call it yourself only on a chart drawn with the patch off.

Returns the layout to draw: layout itself, or, when the reader has zoomed or panned and layout.uirevision is unchanged, a copy with the reader’s ranges. A layout with no scaleanchor axis comes back as is, and the chart forgets any view it had.

VM.plotting.fitView(gd)

Puts a chart’s recorded view back on screen, fitted to its current box. autoResize calls it after every resize.

Returns Plotly’s relayout promise, or null when there is no view to restore (no scaleanchor axis, no explicit range, every axis autoscaled) or Plotly isn’t loaded.

VM.plotting.rangeFromRelayout(event, axis)

Reads one axis’s range out of a plotly_relayout event, which spells it either as "xaxis.range": [a, b] or as "xaxis.range[0]" and "xaxis.range[1]".

Returns [lo, hi]; "auto" when the event switched the axis to autorange; null when the event doesn’t set this axis’s range, or sets only one end.

VM.plotting.keepListening(gd, handlers?)

Plotly event listeners that survive a redraw from scratch. Plotly.newPlot – and Plotly.react, when it decides on a full redraw – throws away every gd.on(...) listener on the div. Ones registered here are put back after each such call by the patch, which is how the locked-axes view and draggablePoints keep working when a page calls newPlot twice on one div.

Parameter Type Description
gd HTMLElement The graph div. May be not yet drawn: the listeners go on once newPlot has given it .on.
handlers {event: fn} (optional) e.g. {plotly_relayout: onZoom}. With none, re-attaches everything registered – what the patch does after each call; do it yourself only for a chart drawn with the patch off.

Returns () => void, which removes the listeners this call added.

VM.plotting.installPlotlyPatch()

Runs the patch. Only needed when Plotly arrives later than the bundle and DOMContentLoaded – a dynamic import, say.

Returns true once patched (also when already patched); false when Plotly isn’t on the page.

VM.plotting.fullscreenButton

The fullscreen modebar button, as a Plotly custom-button object: {name: "fullscreen", title, icon: {width, height, path}, click(gd)}, plus two helpers the SVG button shares: available(), whether element fullscreen works on this page (false on iPhone Safari and in an iframe without allow="fullscreen"), and toggle(target), which enters or leaves fullscreen on target and reports a refused request on the console instead of as an unhandled rejection. The patch adds it to every chart; a page touches this only to reuse its glyph (VM.plotting.fullscreenButton.icon – Bootstrap Icons’ arrows-fullscreen), or to add it to a chart built outside the patch via modeBarButtonsToAdd.

Clicking fullscreens the nearest .ojs-chart-block – so the controls bar and legend come along – or, without one, the graph div itself; a second click exits. Before entering it records the chart’s aspect ratio as --vm-plot-aspect-ratio on the div so the CSS can letterbox it.

SVG fullscreen helpers

Charts drawn as inline SVG (Observable Plot, hand-built <svg>) have no modebar. Give the wrapper class="ojs-chart-block ojs-svg-block" and the library appends one persistent fullscreen button pinned to the figure’s top-right corner – see the markup contract. These two pure helpers are what it measures with; they’re exported for unit tests and for a page that wants to do the same arithmetic.
